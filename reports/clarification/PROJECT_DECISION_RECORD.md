# PROJECT DECISION RECORD

Здесь фиксируются все подтвержденные архитектурные и продуктовые решения.

## DECISION 001 — Авторизация (Историческое)
* **Дата:** 2026-07-24
* **Статус:** ACCEPTED
* **Контекст:** Требование пользователя "УБЕРИ АВТОРИЗАЦИЮ ПОЛНОСТЬЮ. ОНО МНЕ НЕ НУЖНО"
* **Принятое решение:** NextAuth полностью отключен на уровне `middleware.ts` и внутри API routes.
* **Evidence:** Лог команд и код `src/middleware.ts` возвращает `NextResponse.next()`.
* **Последствия:** JARVIS доступен любому пользователю, открывшему URL. Система перешла в локальный/изолированный режим доверия.

## DECISION 002 — Главный сценарий (Оркестратор)
* **Дата:** 2026-07-24
* **Статус:** ACCEPTED
* **Контекст:** Ответ на вопрос Q-MVP-01
* **Принятое решение:** Один главный агент-оркестратор управляет всей платформой через голосовые и текстовые команды. Разрозненные специализированные агенты подчиняются оркестратору.
* **Evidence:** Ответ пользователя ("один главный оркестратор который руководит всей платформой/проектом").
* **Последствия:** Основной фокус роутера и контекста должен быть сосредоточен на главном оркестраторе.
* **Затронутые области:** Agent Routing, Command Router, AI Models.
* **Требует реализации:** YES

## DECISION 003 — Локация выполнения (Гибридная модель)
* **Дата:** 2026-07-24
* **Статус:** ACCEPTED
* **Контекст:** Ответ на вопрос Q-EXEC-02
* **Принятое решение:** Все терминальные команды и MCP tools выполняются локально на компьютере (при локальном запуске `npm run dev`). Облачные задачи могут работать на Vercel.
* **Evidence:** Ответ пользователя ("Гибрид (облачные задачи в Vercel, локальные только при локальном запуске npm run dev)").
* **Последствия:** Не нужно писать отдельный Desktop-клиент, всё выполнение интегрируется прямо в сервер `next dev` (или выделенный API-роут/worker, стартующий вместе с ним).
* **Затронутые области:** `LOCAL_AGENT_RUNTIME`, `DEVELOPER_OPERATOR`, Terminal Execution.
* **Требует реализации:** YES

## DECISION 004 — Уровень автономности (Полная свобода)
* **Дата:** 2026-07-24
* **Статус:** ACCEPTED
* **Контекст:** Ответ на вопрос Q-ACT-03
* **Принятое решение:** JARVIS имеет полную свободу на исполнение команд. Подтверждения (Approvals) запрашиваются только на очень опасные действия (rm -rf, deploy). Агент сам выполняет команды после подтверждения.
* **Evidence:** Ответ пользователя ("полная свобода только при очень опасых действиях спрашивать").
* **Последствия:** Внедрение Execution Layer обязательно. Необходима интеграция с доступом к Shell и Filesystem напрямую из процесса Node.js.
* **Затронутые области:** Execution Layer, Terminal, Safety Gates.
* **Требует реализации:** YES
